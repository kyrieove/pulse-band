## 待办条目

### 1. 统一「剩余」口径（三端）

**现状（已核实）**：`agent-quota-utils.ts:5` 的 `toRemainingPercent(used) = 100 - used`；桌面与 MiniBar 都走这个转换显示**剩余**。而 `band-app/src/pages/index/index.ux` 的 `applyCards()`（约 L1086–L1110）拿到 `l.pct5h / l.pct7d` 后**直接当百分比显示**（`val = pct + '%'`）并按该值填充进度条（`fillW = Math.round(140 * pct / 100)`）——也就是手环显示的是**已用**，卡片标题却只写 `5h` / `7d`，方向没标。

**要做**：
- 手环端在 `applyCards()` 里把 `pct` 转成剩余（`100 - pct`，同样 clamp 到 0–100），数值、估算分支（`'~' + pct + '%'`）、进度条填充宽度三处全部用剩余值。
- 手环卡片标题从 `5h` / `7d` 改成 `5h 剩余` / `7d 剩余`（或在现有 80px/164px 布局里放得下的等价短标签；放不下就先量宽度再决定，不要靠缩字号硬塞）。
- 检查手环的告警/变色阈值：如果原来是按「已用 ≥ X」判定的，改成剩余口径后阈值要相应反转，不能留下方向反了的配色。

**验收**：同一份快照下「已用 20%」在客户端、MiniBar、手环都显示「剩余 80%」，进度条/圆环填充方向与数字一致；`pct` 为 `null`、0、100 三种情况分别可区分（`--` / `0%` / `100%`），不出现 `NaN%` 或 `100%` 与「无数据」混淆。

### 2. 把「可信度」和「新鲜度」拆开表达

**现状（已核实）**：`MiniBar.tsx:496` 只在 `currentQuota?.authoritative === false` 时显示 `Est`，其余一律 `Live`——**包括额度缺失的分支**，于是「没数据」也被标成 `Live`。`useQuotaState.ts` 刷新失败时保留旧数据但不向页面暴露失败状态。手环 `index.ux` 约 L928、L959 的部分请求失败分支不改写屏幕提示，旧的 `Running` 会继续挂着。

**要做**：定义一组三端共用的状态词（放在 `agent-quota-utils.ts` 里导出，手环端用等价的中文短词）：
`正常 / 估算 / 暂无数据 / 需登录 / 连接中断`。
- MiniBar：额度缺失时不得显示 `Live`；`Est` 与 `Auth` 这类缩写换成能看懂的短词。
- `useQuotaState`：增加一个失败态（例如 `lastError` + `lastUpdatedAt`），保留旧数据的同时让页面能显示「上次更新 …」。顶栏那个时间要明确写成「收到快照」之类的措辞，因为它是前端拿到快照的时间，不是数据源的更新时间——不要写成「数据更新于」。
- 手环：连接中断时用小而**持续可见**的提示，且必须覆盖掉旧的 `Running` 文案。

**验收**：分别构造 首次读取失败 / 成功后失败 / 估算 / 需重新登录 / 恢复成功 五种情况，每种都能从界面上看出当前数据是否仍然有效。旧数据可以留，但必须带标记。

### 3. 低额度告警优先于重点卡配色

**现状（已核实）**：`AgentCard.tsx` 主数字固定用 `anchor-text`，7 天数值走弱化小字（L89 附近 10px）；`AgentSection.tsx` 虽然算了两周期中更严重的状态（L120/L125 附近），但重点卡配色没体现；`OverviewPage.tsx:119` 柱图的 5h 柱按阈值变色，图例却写死绿色。

**要做**：
- 把「当前重点查看哪个 Agent」（品牌色/强调）与「哪个周期快耗尽」（告警）分成两套视觉通道。
- 任一周期进入 warning/critical 时，在卡片上加一条**文字**短提示（如「7 天额度偏低」），不依赖颜色也能读出是哪个周期受限。
- 危险态的文字与颜色优先级高于重点卡的装饰性配色。
- 修 `OverviewPage.tsx:119` 附近图例与实际柱色不一致的问题。

**验收**：短周期足/长周期紧、短周期紧/长周期足、双周期正常，三种状态在灰度截图下也能分辨受限周期。

### 4. 让「显示 Agent 状态」开关兑现文案

**现状（已核实）**：`App.tsx:39` 有 `showAgents` state，L113 传给 `<MiniBar showAgents={...}>`，L172 传给概览侧；但 `MiniBar.tsx:9` 只在 props 类型里声明了 `showAgents`，**全文件没有任何一处消费它**；概览的 Agent 卡片渲染也不受它控制。实测关闭开关后 MiniBar 仍显示圆环、额度和 `Running: exec`，概览仍显示 Agent 卡片。

**要做**（二选一，先在回复里说明你选了哪个再动手）：
- **A（接通）**：明确开关控制范围 = 「Agent 的运行状态与额度展示」，在 MiniBar 与概览两处真正消费 `showAgents`，并保证跨窗口同步（MiniBar 是独立窗口，state 要能传到）。关闭时给出「已按设置隐藏」的占位，而不是一片空白。
- **B（移除）**：如果接通成本高于价值，直接把这个开关从设置页移除，连同 `App.tsx` 里的死 state 和 `MiniBar` 里没人用的 props 声明一起清掉。

另外：`SettingsPage.tsx:167–170` 四个「即将支持」的 KV 和 L176 附近那个 `aria-disabled` 的假按钮，从正式界面撤下或收成一行说明文字。不要让四个「即将支持」填满环境信息卡。

**验收**：开关切换后，概览与独立 MiniBar 的变化与开关说明文字一致；切页、重启应用后行为一致。未开放功能不再看起来像可点击的操作。

### 5. 手环管理页给出明确的「下一步」

**现状（已核实）**：页面显示「尚未配置手环」时，右上角按钮却叫「重新配置」；下方并排放着未激活的连接步骤、内置安装、第三方 RPK 两张大卡；`OtherAppInstall.tsx:158` 提示「请先在「手环」页连接手环」——可用户就在这一页。`BandManagementPage.tsx:117–118`：`installMsg` 无论成功失败**一律用 `var(--status-error)` 渲染**，所以「已安装」也是红的（L62 生成该文案）。`useBandConnection.ts` 的连接错误没在本页汇总成错误摘要 + 重试入口。

**要做**：
- 按状态只给**一个**主操作：未配置→「配置手环」；已配置未连接→「连接」；连接失败→「重试连接」；已连接→「安装 / 重装 Pulse 手环端」。第三方 RPK 降为次级入口。
- 修 `installMsg` 的配色：成功用 success 色、失败用 error 色，文案也分开。
- 连接开始后，进度条显示当前步骤；失败时指出失败在哪一步，并就地给重试按钮。
- 去掉 `OtherAppInstall.tsx:158` 那句在本页自相矛盾的提示。

**验收**：未配置 / 已配置未连接 / 连接中 / 失败 / 已连接 / 安装成功 / 安装失败——每个状态都能看出当前情况 + 一个可执行的下一步。真实设备上的连接与安装另行验证，你不要声称验证过。

### 6. 向导进度来自操作结果，不是访问过

**现状（已核实）**：`SetupWizard.tsx` 用 `idx < currentIndex` 就把之前的步骤标成 completed（L56/L76 附近），同时允许点步骤自由跳转；底部「下一步 / 完成向导」不依赖真实的连接、安装或额度验证结果。

**要做**：把状态拆成 `已访问 / 已跳过 / 已成功` 三种，只有对应操作确认成功才显示完成标记。保留用户稍后完成的自由，但按钮文案写成「跳过，稍后配置」。最后一页汇总实际完成项与未完成项。

**验收**：直接跳到后面的步骤、中途退出、重新进入、失败后重试——任何路径都不会把没执行的操作画成成功。

### 7. MiniBar 区分 待命 / 思考中 / 执行中 / 已完成 / 出错

**现状（已核实）**：`MiniBar.tsx` 约 L474、L647 只挑 `thinking / running_tool` 的会话显示工作状态，其余一律回落到 `Ready`；而手环 `index.ux:1043` 附近是区分 `Done` / `Error` 的。于是任务刚完成或刚失败时，MiniBar 显示 `Ready`，手环显示 `Done`/`Error`，两端含义不一致。

**要做**：为当前选定 Agent 保留最近一次的明确结果，状态词统一成 `待命 / 思考中 / 执行中 / 已完成 / 出错`（与第 2 条的状态词表放在一起维护）。完成和错误不要立刻塌缩成「没有会话」。只改状态文字与其保留逻辑，**不要**引入持续闪烁、新的大面积通知或新动画。

**验收**：同一会话依次走完五种状态；失败后不能只剩 `Ready`，完成后能看出已结束。
