# Pulse 客户端、悬浮窗与手环 UI 改进意见

日期：2026-09-11。范围：审查与建议，不实施产品修改。

方法：双代理独立评估（设计：`ui_design_review`；静态证据：`ui_evidence_review`），主审补充当前 Electron 构建的画面检查及一项开关行为检查。

## 总体判断

**建议保留现有视觉方向，先解决“读到的数据是什么意思、是否仍然有效、下一步能做什么”，再调整排版。**

客户端的浅绿灰色体系、额度大数字，以及悬浮窗的黑底圆环已经形成各自明确的用途。手环一页一个 Agent、上下两个额度周期，也适合抬腕快速查看。三端不必强行采用完全相同的外观，但数据口径、告警含义和状态词应一致。

本次最值得优先处理的三件事：

1. **统一“已用 / 剩余”口径。** 当前桌面与悬浮窗使用剩余比例，手环源码直接显示已用比例，手环卡片没有明确标注方向。
2. **让状态标记准确。** 未知数据、旧数据、估算、需要登录和连接中断，不应给人同样的“实时正常”印象。
3. **让界面操作有明确结果。** “显示 Agent 状态”开关实际未影响相关展示；手环管理页的首次配置、连接和重试入口也需要更清楚。

## 一、三端应共同遵守的规则

### 1. P1：统一额度方向，直接写出“剩余”

**观察。** 桌面的 `toRemainingPercent()` 使用 `100 - usedPct`，MiniBar 也复用该转换。状态接口将原始 `pct5h / pct7d` 发给手环，手环 `applyCards()` 直接拼成百分比，并按该值填充进度条。手环卡片标题只有 `5h / 7d`。

**建议。** 三端默认都显示“剩余”；手环改用“5h 剩余 / 7d 剩余”或同等清楚的短标签。进度条和圆环的填充方向与数字保持一致。如果决定手环保留“已用”，必须显式标注，不能让用户靠计算推断。剩余减少时的告警规则也应一并统一。

**验收。** 用同一份非对称额度快照检查三端，例如“已用 20%”应统一呈现“剩余 80%”。该数值是未来验收输入示例，不是本次实测数据。再检查缺失、0% 与 100% 的区别。

依据：[额度转换](../src/renderer/components/pulse/agent-quota-utils.ts) L5；[状态接口](../src/main/services/status-server.ts) L57；[手环页面](../band-app/src/pages/index/index.ux) L29、L1101。

### 2. P1：将“数据来源可信”与“刚刚更新”分开表达

**观察。** MiniBar 只在 `authoritative === false` 时显示 `Est`，其他情况默认显示 `Live`，其中包括额度缺失的分支。客户端刷新异常时保留旧数据，但没有向页面暴露失败状态；顶栏的更新时间是前端拿到快照的时间。手环曾成功加载数据后，部分请求失败分支不会改写屏幕提示。

**建议。** 建立简洁的共同表达：正常数据、估算、暂无数据、需登录、连接中断。保留旧数据时同时标出“上次更新”，而不是只保留原有数字。`authoritative` 说明来源可信程度，不能单独证明新鲜度；没有可靠的源更新时间时，应明确描述已有时间的含义，例如“收到快照”。手环连接中断时使用小而持续可见的提示，避免旧的 Running 状态继续制造实时工作的印象。

**验收。** 分别检查首次读取失败、成功后失败、估算、需要重新登录、恢复成功。旧数据可以保留，但用户必须能看出它当前是否有效。不要用一次正常截图代替这些状态检查。

依据：[MiniBar](../src/renderer/components/minibar/MiniBar.tsx) L496；[额度读取](../src/renderer/hooks/useQuotaState.ts) L43；[手环失败处理](../band-app/src/pages/index/index.ux) L928、L959。

### 3. P1：告警应指出受限周期，不被强调配色覆盖

**观察。** 当前概览中，Codex 的重点卡使用绿色系强调，7 天的低剩余值处在卡片底部的小字中。源码虽然计算了两个周期中更严重的状态，但重点卡主数字固定使用 `anchor-text`，7 天数值仍采用弱化文字样式。柱图的 5 小时柱按阈值变色，而图例固定为绿色。

**建议。** 将“正在重点查看哪个 Agent”和“哪个周期即将耗尽”分开。保留主数字，同时在有必要时明确写“7 天额度偏低”等短提示；危险状态的文字和颜色优先于装饰性的重点卡样式。三端用一致的剩余口径决定告警，不让品牌颜色兼任全部告警含义。

**验收。** 对比短周期充足而长周期不足、短周期不足而长周期充足、双周期正常三种状态；不用颜色也能识别受限周期。

依据：[AgentSection](../src/renderer/components/pulse/AgentSection.tsx) L130、L172；[AgentCard](../src/renderer/components/pulse/AgentCard.tsx) L59、L91；[概览柱图](../src/renderer/components/pulse/OverviewPage.tsx) L119。

## 二、客户端

### 4. P1：处理无实际效果的显示开关，降低未开放功能的存在感

**观察。** 本次实际关闭“显示 Agent 状态”后，MiniBar 仍显示圆环、额度及 `Running: exec`，概览仍显示 Agent 卡片。源码中该状态没有控制概览渲染，MiniBar 也未消费对应属性。另有“导出记录”“检查更新”和多项“即将支持”的环境信息占用正式界面空间。

**建议。** 先明确开关控制的是运行状态、额度还是整组 Agent 内容，再接通相应显示行为和跨窗口同步；没有可兑现行为时先移除。尚未开放的功能可以从主操作区撤下，或集中成一个简短说明。不要让四个“即将支持”填满环境信息卡。

**验收。** 关闭与开启开关后，概览及独立 MiniBar 的变化与说明一致；切页和重启后的行为也符合约定。未开放功能不会看起来像一个可完成的操作。

依据：[设置页](../src/renderer/components/pulse/SettingsPage.tsx) L124、L166；[App](../src/renderer/App.tsx) L145；[MiniBar](../src/renderer/components/minibar/MiniBar.tsx) L70。

### 5. P1：手环管理页应直接回答“下一步做什么”

**观察。** 本次页面显示“尚未配置手环”，右上角却叫“重新配置”；下方是未激活的连接步骤、内置安装与第三方 RPK 两张大卡。第三方安装区提示“请先在「手环」页连接手环”，但用户已经身处该页。源码中的连接错误没有在本页形成明确的错误摘要和重试入口。

**建议。** 按状态安排一个主操作：未配置时“配置手环”，已配置未连接时“连接”，失败时“重试连接”，连接后再突出“安装 / 重装 Pulse 手环端”。第三方 RPK 安装作为次级入口。进度条在开始连接后显示当前步骤和失败位置。内置安装成功与失败使用各自的文案和样式；目前“已安装”也套用错误色，应修正。

**验收。** 未配置、已配置未连接、连接中、失败、连接成功、安装成功和安装失败，每个状态都能指出当前情况及一个可执行的下一步。连接与安装本身需另外做真实设备验证。

依据：[手环管理](../src/renderer/components/pulse/BandManagementPage.tsx) L21、L84、L118；[连接状态](../src/renderer/hooks/useBandConnection.ts) L83；[RPK 提示](../src/renderer/components/pulse/OtherAppInstall.tsx) L158。

### 6. P1：向导进度应来自操作结果

**观察。** 向导根据 `idx < currentIndex` 将之前的步骤标为 completed，同时允许点击步骤跳转；底部“下一步 / 完成向导”没有依赖真实连接、安装或额度验证结果。

**建议。** 分清“已访问”“跳过”和“已成功”。保留用户稍后完成的自由，但用“跳过，稍后配置”明确表达；只有对应操作确认成功才显示完成标记。最后一页汇总实际完成项及未完成项。

**验收。** 直接跳到后一步、退出、重新进入、失败后重试，都不会把未执行操作画成成功。此项目前来自源码检查，未执行真实配对向导。

依据：[SetupWizard](../src/renderer/components/setup/SetupWizard.tsx) L56、L76、L91、L281。

### 7. P2：优先提高关键小字的可读性

**观察。** 当前画面中数字很清楚，但重置时间、7 天额度、说明文字明显更细、更弱。字体栈为拉丁无衬线配中文宋体，正文默认字重 300；卡片时间和长周期额度为 10px，数据来源标记为 9px。宋体与大号粗数字的差别是当前风格的一部分，但放到操作说明和状态信息上，会增加阅读负担。

**建议。** 保留页面标题的风格，先试调关键业务文字到约 12–13px、常规字重，并减少同一行中互相竞争的字号。中文操作文字可对比清晰的屏幕无衬线字体；若保留宋体，也应优先提高小字字重。次要装饰可以淡，重置时间、错误与周期含义不能淡到需要凑近看。

**验收。** 在实际显示器的 100%、125%、150% 缩放及浅深主题下，对照重置时间、7 天额度和连接说明；检查截断、换行和阅读感受。本次未做完整字体回退识别或对比度测量。

依据：[字体与字重](../src/renderer/index.css) L69、L208；[卡片小字](../src/renderer/components/pulse/AgentCard.tsx) L89；[来源标记](../src/renderer/components/pulse/OverviewPage.tsx) L157。

### 8. P2：让概览下半区提供更有用的信息

**观察。** 双周期柱图占据下半页的主要面积，重复顶部卡片的数据，却没有柱上百分比和刻度。右侧来源列表再次列出三个 Agent，未连接手环卡也留有较大空白。用户需要上下对照才能读出具体数值。

**建议。** 最小改进是给柱子补“剩余百分比”，明确图例；同时压缩手环状态卡的无信息空白。若以后进一步整理布局，可将下半区改为紧凑的“双周期剩余 + 重置时间”比较区，把空间用于最接近受限的周期或需要处理的异常。不要为了占满窗口继续增加卡片。

**验收。** 单看比较区就能回答“哪个 Agent 的哪个周期更紧张、还剩多少”；未提供、0% 与正常数值可区分。缩小到产品允许的最小窗口后，主要操作与关键数值仍可见。

依据：[OverviewPage](../src/renderer/components/pulse/OverviewPage.tsx) L103、L119、L170。

## 三、悬浮窗 MiniBar

### 9. P1：区分待命、工作、完成和出错

**观察。** MiniBar 只选取 thinking / running_tool 的会话来显示工作状态，其他情况统一回到 `Ready`；手环源码则区分 Done 和 Error。因此任务刚完成或刚失败时，三端可能给出不同含义的反馈。

**建议。** 为当前选定 Agent 保留最近的明确结果，用“待命 / 思考中 / 执行中 / 已完成 / 出错”或一致的对应词。完成和错误不应立即与“没有会话”混为一谈。先完善轻量的状态文字，不必引入持续闪烁或新增大面积通知。

**验收。** 用同一会话依次检查五种状态；失败后不能仅剩 Ready，完成后能辨认已结束。此项未做真实任务生命周期验证。

依据：[MiniBar 会话选择与状态](../src/renderer/components/minibar/MiniBar.tsx) L474、L647；[手环状态映射](../band-app/src/pages/index/index.ux) L1043。

### 10. P2：保留圆环与详情分层，压缩重复时间并补操作提示

**观察。** 实际横向条的 Logo、圆环和百分比易于区分；展开后两个周期位置稳定。详情中同时出现“几小时后重置”和“重置于某时”，加上标题、可信度缩写、状态胶囊与版本号，信息明显变密。固定和收起按钮在源码中只有 20px 大小；收起态没有直接说明百分比对应哪个周期。

**建议。** 保留现有黑底、品牌 Logo 和圆环轮廓。默认突出“5 小时剩余”，详情保留一个主要重置表达，绝对时间作为次级信息；底部版本号可以进一步让位。缩写 `Est / Auth` 改为容易理解的短提示。设置页或首次展示时用一行说明“悬停查看、点击固定、右键设置”；不必把所有说明常驻在浮条上。按钮图标可以保持小，但扩大实际点击区域。

**验收。** 在浅、深桌面背景上检查条和卡片的文字；快速移入移出、固定后切换 Agent、收起与恢复时，用户能理解当前状态。透明区域的鼠标穿透、拖动和动画流畅度必须在原生环境另行验证，本次截图不能证明这些行为。

依据：[MiniBar 详情](../src/renderer/components/minibar/MiniBar.tsx) L519、L554、L647；[圆环与指针入口](../src/renderer/components/minibar/MiniBar.tsx) L927、L1092。

## 四、手环 UI

### 11. P2：把小屏留给能在抬腕时读懂的内容

**观察。** 当前页面使用 192 × 490 的设计画布；工具名区域宽 164px、字号 12px，重置时间区域只有 80px 宽。卡片中的大百分比和固定位置值得保留。英文状态、中文日期及截断后的传输错误串同时出现在小屏上，理解方式不够统一。

**建议。** 保留“一页一个 Agent、两个周期、底部时间”的结构。优先使用“思考中”“执行工具”“已完成”“连接中断”等短文字；长工具名使用简短展示名，完整名称与技术错误交给客户端诊断。重置时间统一成能放入现有区域的短格式，并让“多久后重置”与“当前时间”明显不同。不要仅靠缩小字号容纳更多内容。

**验收。** 在当前安装版本的手环上检查最长工具名、较长重置时间、暂无数据、错误和估算状态。以正常佩戴距离阅读，检查是否裁切、是否需要反复抬腕。历史照片只能提供外观线索，不能替代此项验收。

依据：[手环布局](../band-app/src/pages/index/index.ux) L146、L215、L257；[错误文案](../band-app/src/pages/index/index.ux) L931、L1124。

### 12. P2：让刷新、分页和退出手势可以被发现

**观察。** 时钟区域点按用于刷新 / 重连，长按用于退出，画面没有对应说明；第一页还绑定右滑退出，其他页右滑主要用于切换 Agent。用户需要记住同一区域的多个隐藏动作。

**建议。** 首次使用时短暂说明左右滑动切换 Agent；连接失败时显示“点按时间重试”之类的就地提示。退出应有稳定、跨页一致的可发现入口，减少切页与退出之间的歧义。沿用设备已支持的实现方式，不为视觉效果贸然引入未验证的动画能力。

**验收。** 从三页分别测试点按、长按、左右滑动、中途取消及恢复；确认不会误退出，也不会困在无法重试的状态。所有手势建议均待真机验证。

### 13. P2：补齐已有语义背后的键盘和焦点行为

**观察。** 当前已有全局焦点样式，不能说产品“没有键盘支持”。但 MiniBar 圆环使用可聚焦的 `div role="button"`，未看到 Enter / Space 激活处理；向导具有模态语义，却未看到焦点迁入、约束和关闭后恢复。导航与主题选择主要通过颜色、勾选表达状态。减弱动态规则只覆盖了 MiniBar 详情卡的部分过渡。

**建议。** 优先让圆环用键盘完成展开、固定、关闭；向导管理焦点并支持可预期的退出方式。为导航和主题补足选中语义，为异步结果提供可读提示。减弱动态时保留文字状态，减少持续呼吸和旋转。

**验收。** 在 Electron 中只用 Tab、Shift+Tab、Enter、Space、Esc 完成相关操作；再检查系统减弱动态设置。原生窗口能否获得焦点也必须一并核实。此项目前主要为源码证据，未完成读屏或原生键盘全流程测试。
