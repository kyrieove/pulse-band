# Pulse 2.0 产品与首次设置重构设计

日期：2026-09-09  
状态：用户已确认设计内容，等待书面规格复核

## 1. 目标

Pulse 2.0 面向普通用户重新设计。产品以 AI Agent 状态和额度为核心，并由 Pulse 自己完成手环首次设置、
Windows 配对、认证、快应用安装和日常通信。

Pulse 2.0 的用户界面、首次设置、错误提示、帮助文档和安装说明不出现历史设备工具名称，也不要求用户
安装或打开其他设备管理程序。

首版正式支持 Windows 11 x64 和 Xiaomi Smart Band 10。开发期间允许中间提交暂时无法完成首次设置，
但整个版本完成并通过真机验收之前不对外发布。

## 2. 实施策略

工作拆成三个连续、可独立提交和验证的子项目：

1. Pulse 2.0 UI 基础与日常页面；
2. 无外部设备工具的首次设置与 Windows 配对；
3. 内置及第三方 RPK 安装闭环与历史内部命名清理。

最终发布要求三个子项目全部完成。开发过程中不制作虚假的可用入口，也不使用假数据伪装尚未接通的能力。

## 3. 信息架构

主窗口使用固定左侧窄导航栏。顶部显示 Pulse 2.0 标识，中部包含“概览”“手环”“设置”，底部显示版本。

### 3.1 概览

内容严格按用户操作顺序排列：

1. 顶部首先显示已配置手环和连接状态；
2. 紧邻状态提供“连接手环”或“断开连接”主按钮；
3. 连接时按钮原位依次显示“正在启动设备服务”“正在连接手环”“正在认证”“已连接”；
4. 下方展示已检测到或已启用的 Agent 卡片。

Agent 卡片默认展示名称、主要剩余额度、重置时间和当前状态。Agent 正在运行时增加任务计时。点击卡片后
展开周期额度和数据更新时间。未检测或未启用的 Agent 不占用概览空间，用户可在设置中控制显示。

手环未连接时，电脑端额度仍然可查看，并明确说明数据尚未同步到手环。日常连接不重复显示手机蓝牙占用
提示，也不弹出连接确认框；这项准备工作只在首次设置中说明。

### 3.2 手环

手环页展示设备名称、连接状态、连接操作和 Pulse 快应用版本。

- 检测到内置快应用新版本时提示用户，由用户点击更新；
- 右上角提供“更换手环”，用于重新进入首次设置；
- 更换手环覆盖现有配置前必须明确说明影响；
- “推送其他快应用”作为高级工具默认折叠；
- 高级工具支持拖入或选择单个 `.rpk`，展示文件名称与大小，用户确认后安装并查看进度和结果；
- 首版不支持批量安装；
- 页面结构允许以后增加表盘设计、导入和管理，但本版不显示不可用的表盘入口。

### 3.3 设置

设置页使用四个分组，不增加第二套导航：

- 外观：亮色/深色主题、悬浮窗开关；
- Agent：检测结果和显示控制；
- 手环同步：设备重新配置等日常偏好；
- 高级维护：诊断、脱敏日志、诊断报告、Hook 和更新。

产品提供亮色和深色两套主题，默认亮色。主题选择立即生效并持久保存。两套主题使用相同布局和信息层级。

高级诊断默认只显示“设备服务正常”“手环未连接”“数据已更新”等普通结论与处理操作。展开后才显示进程、
协议版本、连接阶段、脱敏日志和复制诊断报告。

## 4. 悬浮窗、托盘与生命周期

保留桌面悬浮窗，并同步 Pulse 2.0 的主题和 Agent 显示设置。悬浮窗只显示已启用 Agent 的精简额度和
运行状态，点击后打开 Pulse 2.0 概览页。

关闭主窗口后应用进入托盘，Agent 监控、悬浮窗和已建立的手环连接继续运行。托盘提供：

- 打开 Pulse 2.0；
- 连接或断开手环；
- 退出。

只有选择“退出”才释放手环连接、停止 Pulse Device Core 并结束程序。启动 Pulse 2.0 后不自动连接手环；
用户通过概览页或托盘主动连接。

## 5. 一次性首次设置

没有设备配置时，Pulse 2.0 自动进入首次设置。完成后整套引导隐藏，只显示日常页面。用户可通过手环页
“更换手环”重新进入。

### 5.1 准备

向导说明需要 Windows 11、电脑蓝牙，以及已经通过小米运动健康绑定的手环。引导用户断开手环与手机，
并让手环进入可连接状态。

### 5.2 导入手机日志

用户拖入或选择小米健康研究导出的日志、压缩包或受支持目录。Pulse 只在内存中解析用户选择的内容，
不复制、不留存原始日志。系统自动识别设备信息和 authkey，不向用户展示 authkey 原文。

### 5.3 安全保存凭据

Pulse Device Core 使用 Windows DPAPI 的当前用户范围加密 authkey。普通配置只保存运行所需的非敏感
元数据和 DPAPI 密文。

升级时对现有明文配置执行一次原子迁移：先生成加密配置并验证能够解密，再替换旧配置。迁移失败时保留
原配置并提示重新设置，不能删除仍然唯一可用的凭据。

日志、诊断、错误报告和 UI 不包含完整设备地址、authkey、会话密钥或额度正文。解密后的 authkey 只在
连接和认证所需的内存范围内使用。

### 5.4 Windows 配对

Pulse 根据导入的设备信息搜索目标手环并发起 Windows 系统配对。Windows SSP 或手环要求的安全确认必须
正常显示，Pulse 不尝试绕过系统确认。

应用内配对失败时，Pulse 打开 Windows 蓝牙设置并继续检测目标设备。用户在系统设置完成配对后，向导自动
返回连接步骤。

### 5.5 连接与认证

`pulse-core` 建立 SPP/RFCOMM 连接并复用现有 Session 认证实现。UI 接收结构化阶段状态，不通过解析日志
文本判断进度。失败时保留已完成步骤，提供重试和脱敏错误。

### 5.6 安装内置快应用

首次设置自动安装打包内的 `band-app.rpk`，显示真实的准备、传输、校验和完成进度。安装完成后提示用户
在手环打开 Pulse。

### 5.7 完成验证

Pulse 检测状态查询、`__hs__` 握手和额度请求。手环正常显示额度后，首次设置完成并隐藏。

## 6. 技术边界

### 6.1 子项目 1：UI 基础

保留现有 Electron、React 和 Rust core 架构。本阶段建立主题变量，重做三个主页面、连接反馈、Agent 卡片、
悬浮窗和托盘，并清除用户可见内容中的历史设备工具表述。

为避免 UI 重构与底层重构互相干扰，本阶段暂时允许内部保留历史类名。首次设置页面只建立真实状态接口，
不使用假数据把未实现能力表现为成功。

### 6.2 子项目 2：首次设置与安全凭据

增加边界清楚的设备配置服务，负责内存解析、向已鉴权本地 RPC 交付设备信息、DPAPI 持久化、旧配置迁移、
Windows 设备枚举和配对状态映射。

Core 向 UI 发送不含敏感字段的结构化状态。配对成功后复用现有 RFCOMM 和 Session 认证，不复制第二套连接
或认证实现。

### 6.3 子项目 3：RPK 安装与清理

先根据可记录来源和真机行为确认安装协议，再实现最小安装能力。支持首次设置自动安装、内置应用版本检测与
手动更新，以及折叠高级工具中的单个第三方 RPK 安装。

安装失败不得报告成功。完成安装闭环后，统一把内部历史客户端、桥接器、日志标签和文件名改为 Pulse Core /
Device 语义，并删除产品内容中的历史依赖文案。

## 7. 状态与错误处理

长流程使用统一状态模型：

```text
idle → preparing → working → success
                         ↘ error
```

连接细分为启动设备服务、查找手环、建立 RFCOMM、认证和已连接。首次设置细分为日志解析、保存凭据、Windows
配对、认证、安装和业务验证。

用户可处理错误及对应动作：

| 情况 | 默认动作 |
|---|---|
| 未找到手环 | 检查蓝牙和手环可发现状态后重试 |
| Windows 配对未完成 | 重新发起或打开系统蓝牙设置 |
| 日志没有有效设备信息 | 选择最新日志重新导入 |
| 认证失败 | 重新导入日志或重新配置设备 |
| RPK 不合法 | 拒绝安装并说明文件问题 |
| 传输中断 | 保留当前页面并允许重新开始 |
| DPAPI 无法解密 | 说明配置属于其他 Windows 用户或电脑，重新设置设备 |

普通界面显示短错误和下一步操作。高级维护页显示错误代码、发生阶段、时间和经过脱敏的诊断报告。

## 8. 测试与验收

### 8.1 自动测试

- UI：主题、页面状态、Agent 筛选、连接进度、首次设置状态和折叠高级工具；
- Core：DPAPI 往返、配置原子迁移、损坏密文、配对状态映射和安装状态机；
- 现有回归：已有 RPC、RFCOMM 帧、认证、数据泵和客户端契约测试继续通过。

### 8.2 现有电脑真机回归

使用当前已配对手环确认连接、认证、额度显示、手动断开和重新连接没有回退。

### 8.3 干净电脑最终验收

在同学的干净 Windows 11 x64 电脑上验收。起始状态为：未安装历史设备工具、没有 Pulse 配置、没有现成
手环 Windows bond。

完整路径必须通过：

```text
安装 Pulse 2.0
→ 导入手机日志
→ Windows 系统配对
→ SPP/RFCOMM 连接与认证
→ 自动安装 Pulse 快应用
→ 手环打开 Pulse
→ 显示真实额度
→ 手动断开并重新连接后恢复
```

Windows 蓝牙关闭再开启后的自动恢复，以及手环离开范围再返回后的自动恢复，不属于首版验收标准。

## 9. 发布门槛

- 三个子项目全部完成；
- 自动测试全部通过；
- 当前电脑的既有用户回归通过；
- 干净 Windows 11 x64 电脑的完整首次设置真机验收通过；
- Pulse 2.0 的界面、向导、错误和用户文档中不存在历史设备工具名称；
- 用户单独决定发布版本。

未达到以上条件时只保留本地开发构建，不对外发布。
