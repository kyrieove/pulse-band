# Pulse 表盘工作室 V1 设计

日期：2026-09-13
状态：设计已获用户认可；尚未进入实现计划与编码阶段

## 1. 目标

在 Pulse 中加入面向高级创作者的 Xiaomi Smart Band 10 表盘工作室。用户可以在自由画布中组织图层、素材、动态数据、独立 AOD 和 PNG 序列动画，保存为开放的源码工程，生成 `.face` / `.bin`，通过校验后使用 Pulse 现有链路安装到手环。

工作室不是模板换肤工具，也不是通用图片编辑器。它要覆盖一套完整、可重复编辑、可审查、可迁移的表盘制作流程：

1. 新建或打开源码工程。
2. 导入和制作表盘素材。
3. 在 212×520 画布上自由布局组件。
4. 用模拟数据检查不同状态。
5. 独立设计 AOD，配置序列帧动画。
6. 校验、构建、回读检查并生成产物。
7. 首次确认风险后安装到真实 Band 10。

## 2. 已确认的产品决策

- 产品定位：专家级自由创作，不做受限模板编辑器。
- 工程形式：使用可见的普通文件夹，而不是 Pulse 私有数据库。
- 工程模型：兼容 `band10-toolkit` 的 `manifest.json + layout.json + assets/` 源码形式。
- 编辑方式：三栏专业工作台；默认可视化设计，提供“设计 / 源码”模式切换。
- 保存方式：显式保存；编辑过程自动保存恢复草稿；支持撤销、重做与外部文件冲突提示。
- V1 设备：只支持 Xiaomi Smart Band 10，分辨率固定为 212×520。
- V1 内容：自由图层、常用动态数据、独立 AOD、PNG 序列动画。
- V1 不支持：视频、模拟指针、点击跳转、脚本资源和固件可编辑组件。
- 二进制导入：不承诺把现有 `.bin` 反编译成可编辑工程；`.bin` 只用于检查、预览和安装。
- 数据预览：V1 使用完整模拟器；电脑读取手环实时健康数据不是前置条件。
- 打包：默认使用内置开源 native packer；用户可选配自己取得的 Mi Create `compile.exe`。
- 安装安全：首次安装自制包必须确认风险；以后通过全部检查的工程可快捷构建并安装。
- 许可证：Pulse 继续采用 MIT，不复制或链接 Mi Create 的 GPL-3.0 实现，不分发其第三方闭源编译器。
- 实施顺序：先做构建内核到真机的纵向技术验证，再建设完整编辑器。

## 3. 上游研究与采用边界

### 3.1 band10-toolkit

项目：<https://github.com/utsabfdahal/band10-toolkit>

适合吸收进 Pulse 的部分：

- MIT 许可的规范模型、Schema、数据源表和语义校验器。
- 212×520 React/SVG 预览思路与数据模拟模型。
- 素材标准化、FPRJ/GMF 导出、native o66 packer。
- 表盘二进制解析、图片/RLE 编解码和打包后回读检查。
- active face、AOD 和序列帧动画的工程表达。

Pulse 不把整个仓库作为运行时外部依赖，也不在首次使用时联网下载。实现阶段应选取必要模块，以带来源记录的源码快照纳入仓库，并记录：

- 上游仓库地址与 commit。
- 上游 MIT 许可证文本。
- 纳入的文件及 Pulse 修改摘要。
- 后续同步上游时的差异审查方式。

上游 README 声称 native 产物曾在真实 Band 10 上安装显示，但其限制文档仍保留“缺少实体 o66 验证”的记录。两处证据口径不完全一致，因此 Pulse 不以该声明代替自己的真机验证。

参考：

- 架构：<https://github.com/utsabfdahal/band10-toolkit/blob/main/docs/architecture.md>
- 创作模型：<https://github.com/utsabfdahal/band10-toolkit/blob/main/docs/authoring.md>
- 安装与外部编译器：<https://github.com/utsabfdahal/band10-toolkit/blob/main/docs/installation.md>
- 已知限制：<https://github.com/utsabfdahal/band10-toolkit/blob/main/docs/limitations.md>

### 3.2 Mi Create

项目：<https://github.com/ooflet/Mi-Create>

Mi Create 提供较成熟的 FPRJ 编辑工作流、快速 AOD、实时预览、多语言和组件式创作经验。Pulse 吸收这些产品能力与公开格式知识，但不复制其实现：

- Mi Create 源码采用 GPL-3.0，与继续保持 MIT 的 Pulse 不适合直接合并。
- Mi Create 使用的第三方编译器不是开源软件，Pulse 不下载、不附带、不代为分发。
- 用户可在高级设置中明确选择自己已有的编译器路径，Pulse 只提供受控适配器。
- 外部编译器的输出、日志和失败必须与 native 后端分开标识，不能混称为 Pulse native 构建结果。

### 3.3 格式兼容

- Pulse 工程的权威模型是规范 JSON，不以 FPRJ 或 GMF 作为内部状态。
- V1 支持 `.fprj` 导入和导出。
- V1 支持 GMF `wfDef.json` 导出，暂不承诺可靠导入。
- FPRJ 导入必须生成迁移报告：已映射、降级、未支持、无法识别的内容逐项列出。
- 不认识的字段不得静默删除。原文件保持不变，转换结果写入用户选择的新工程目录。

## 4. 系统架构

```text
普通工程目录
manifest.json + layout.json + assets/
        │
        ▼
Renderer：三栏 Studio
图层/素材 │ 212×520 画布 │ 属性/模拟器/源码
        │ typed IPC
        ▼
Main：Watchface Authoring Service
工程读写 │ 恢复草稿 │ 路径检查 │ 构建任务
        │
        ├── 内置 MIT 核心
        │   Schema → 校验 → 素材标准化 → native 打包 → 回读
        │
        ├── 格式兼容
        │   FPRJ 导入/导出 → GMF 导出 → 迁移报告
        │
        └── 可选外部编译器适配器
            用户自备 compile.exe，不下载、不分发
        │
        ▼
.bin/.face + preview.png + build-report.json
        │ 首次风险确认
        ▼
现有 WatchfaceService / pulse-core 安装链路
        ▼
Xiaomi Smart Band 10
```

### 4.1 Renderer 边界

Renderer 负责交互和内存中的编辑草稿，不直接访问任意文件系统、不启动编译器、不调用底层设备协议。所有工程读写、文件选择、构建和安装都经 preload 暴露的最小类型化 IPC。

### 4.2 Main 边界

新增 `WatchfaceAuthoringService`，协调四类职责清晰的单元：

- `ProjectService`：创建、打开、保存、外部变更检测、最近项目。
- `RecoveryService`：把未保存草稿写入 Pulse `userData`，按规范化工程路径建立恢复键；恢复数据不污染用户源码目录。
- `BuildService`：运行校验、素材处理、打包、回读检查和取消。
- `CompatibilityService`：FPRJ/GMF 转换和外部编译器适配。

设备安装继续复用现有 `WatchfaceService.install()`，不建立第二条 BLE 或 RPC 通道。

### 4.3 任务模型

校验、构建、素材转换和安装使用显式任务状态：

```text
idle → validating → building → inspecting → ready
                  ↘ failed
                  ↘ cancelled

ready → installing → installed
                  ↘ install-failed
```

构建成功和设备安装成功是两个不同事实，界面与日志必须分别展示。取消只影响当前本地任务；如果设备安装已经提交给 core，则遵循现有安装链路的真实取消能力，不伪造“已取消”。

## 5. 工程与数据模型

### 5.1 源码目录

```text
my-watchface/
├── manifest.json
├── layout.json
└── assets/
    ├── backgrounds/
    ├── digits/
    ├── icons/
    ├── weather/
    └── animation/
```

`build/` 与 `dist/` 是可重建产物，不是工程权威数据。恢复草稿、最近项目和 UI 偏好存入 Pulse `userData`。

### 5.2 V1 组件

- `image`：单张静态图片。
- `number`：由数字素材集渲染的动态数值。
- `image-list`：根据数据值选择图片，如星期、天气、电量档位。
- `progress`：条形或弧形进度；若 native 后端的目标属性仍未验证，则阻止安装或明确要求实验模式。
- `animation`：尺寸一致的 PNG 序列帧、帧间隔、循环次数。
- AOD：独立于 active face 的组件列表和素材集合。

普通文本标签在构建时栅格化成图片；动态数字使用数字图集。V1 不把 TTF 作为运行时字体打进手环。

### 5.3 数据源

工作室展示 toolkit 已恢复的已知数据绑定，包括：

- 小时、分钟、秒及其高低位，日期、月份、年份、星期、AM/PM。
- 天气状态、摄氏/华氏温度。
- 电量、蓝牙、锁屏、睡眠状态。
- 心率、心率区间、步数、步数目标、卡路里、卡路里目标。
- 站立次数、压力、睡眠评分。

每个数据源带能力状态：

- `verified`：在当前 Pulse 构建和目标手环上验证。
- `mapped`：有公开逆向映射和构建支持，但尚未完成 Pulse 真机验证。
- `unsupported`：当前后端不支持，不允许构建。

模拟器为所有可编辑数据源提供正常值和边界场景。未来的真实设备数据提供器复用同一接口，不改变工程文件格式。

## 6. 工作室交互

### 6.1 总体布局

- 顶栏：返回、工程名、未保存状态、预览、校验、构建、构建并安装。
- 左栏：图层树与素材库；支持排序、分组、显隐、锁定和拖入画布。
- 中央：212×520 画布；支持缩放、平移、框选、多选、拖动、缩放、对齐线和像素坐标。
- 右栏：选中对象属性、数据绑定、模拟值；可切换到源码模式。
- 底部：校验问题、构建日志、迁移报告和动画时间轴，按任务展开。

### 6.2 设计 / 源码切换

- 设计模式修改规范内存模型。
- 源码模式编辑 `layout.json` 草稿。
- JSON 只有在语法和 Schema 均通过后才同步回画布。
- 非法源码保留在编辑器中并展示错误，不覆盖上一个有效画布模型，也不能保存为正式工程或构建。
- 从设计切回源码时保持稳定格式，避免每次操作产生无意义的大范围 diff。

### 6.3 保存与恢复

- `Ctrl+S` 或保存按钮才原子替换工程文件。
- 画布操作进入有限容量的撤销/重做历史。
- 恢复草稿按节流周期写入 `userData`，成功保存后清理对应恢复项。
- 文件在外部变化时暂停自动覆盖，提供“重新载入”“保留当前草稿”“查看差异”。
- 关闭未保存工程时确认；崩溃后首次重开提供恢复选择。

## 7. 素材助手

V1 提供表盘制作所需的最小素材处理：

- 导入 PNG、SVG。
- 裁切、缩放和透明边界清理。
- 显示尺寸、像素格式、颜色数量和预计资源占用。
- 生成确定性的 RGBA PNG，并尽可能使用调色板/RLE 打包。
- 从用户选择的本机字体生成数字图集，包括数字、负号、冒号和常用单位符号。
- 导入等尺寸 PNG 序列，调整顺序和帧间隔，播放 active 预览。
- 对尺寸不一致、帧数过多、刷新过快和预计资源过大的动画给出阻断或警告。

Pulse 不提供画笔、蒙版、滤镜、复杂矢量路径等通用图片编辑功能。字体只在本机栅格化；工程记录来源信息，导出或分享前提示用户确认字体与素材许可。

## 8. 构建与安装流水线

每次生成可安装包必须执行：

1. 从磁盘加载最近保存的工程快照；未保存草稿先询问是否保存。
2. 运行 JSON Schema 和语义校验。
3. 检查画布边界、组件重叠、资源路径、图片尺寸、动画一致性、AOD 约束和包体预算。
4. 标准化素材并生成确定性中间产物。
5. 选择 native 或用户明确配置的外部后端。
6. 写入临时目标，成功后原子替换 `dist` 产物。
7. 使用独立解析器回读 `.bin`，检查头、偏移、资源、数据绑定和 active/AOD 结构。
8. 生成 `preview.png` 与机器可读 `build-report.json`。
9. 只有无阻断错误时启用安装。
10. 首次安装自制包时展示设备型号、分辨率、后端、已知限制和恢复建议，用户确认后调用现有安装服务。

后续安装仍显示简短检查摘要。切换打包后端必须重新构建，不能复用另一后端的成功状态。

## 9. 错误与安全策略

- Renderer 传入的所有路径视为不可信；Main 使用规范化绝对路径并限制工程内相对素材路径。
- 不允许通过 `..`、符号链接或构建输出路径覆盖工程外文件。
- 工程保存和构建输出使用临时文件加原子替换。
- 外部编译器只在用户显式配置后运行；不拼接 shell 字符串，不继承无关敏感环境变量。
- 日志不记录设备 AuthKey、完整物理地址或用户素材二进制。
- 单个素材失败不产生半成功包；构建失败不改变上一次成功产物。
- 未验证数据源或组件必须有可见状态，不能把模拟器显示正常当成真机能力证明。
- 安装成功以 core 和设备的真实结果为准，不能把“文件已生成”或“请求已发送”显示为安装完成。

## 10. 分阶段交付

### 阶段 0：技术纵切与 Go/No-Go

只纳入生成一个验证工程所需的 toolkit MIT 模块。工程必须同时包含静态图片、时间数字、步数、电量、AOD 和短序列动画。完成：

- Schema 与语义校验。
- native 打包。
- 独立回读检查。
- 通过 Pulse 现有链路安装到当前 Band 10。
- 真机验证 active、动态数据、动画、AOD、唤醒切换和恢复路径。

若核心结构不能可靠安装或设备出现异常，停止后续 Studio 开发，先修正打包器或缩减已验证能力。

### 阶段 1：工程内核

实现项目创建/打开/保存、恢复草稿、外部冲突、统一模型、IPC 边界和构建任务状态。提供最小源码编辑与命令式构建入口作为内核验收面。

### 阶段 2：三栏可视化 Studio

实现图层树、组件库、画布操作、属性面板、数据模拟器、设计/源码切换、撤销/重做和校验面板。

### 阶段 3：素材、AOD 与动画

实现素材助手、数字图集生成、AOD 独立画布和动画时间轴；补齐资源预算与边界检查。

### 阶段 4：Mi Create 兼容

实现 FPRJ 导入/导出、GMF 导出、迁移报告和用户自备 `compile.exe` 适配。所有格式转换使用固定夹具测试，未知信息不得静默丢失。

### 阶段 5：安装体验与发布收口

接入首次风险确认、快捷重建安装、构建历史、失败恢复和完整真机回归。只有已验证能力可作为默认稳定组件发布。

## 11. 验收标准

### 自动化

- 工程 Schema、保存/恢复、外部冲突和路径安全测试。
- 每类 V1 组件的模型、渲染、导出、native 打包和回读测试。
- 数据源映射的双向语义测试，不只检查数字 ID 是否存在。
- FPRJ 导入/导出夹具与迁移报告测试。
- active/AOD 资源隔离、动画帧一致性、包体限制和损坏输入测试。
- 构建取消、失败不覆盖旧产物、外部编译器失败传播测试。
- Renderer IPC 权限边界与敏感信息扫描。

### 目标环境

- Windows 正式 Electron 构建中完成新建、保存、重开和崩溃恢复。
- 同一个工程在模拟器、生成预览和真机显示之间进行截图对照，记录已知差异。
- 最小表盘、综合数据表盘、AOD 表盘和动画表盘分别安装到当前 Xiaomi Smart Band 10。
- 验证切换、重启、进入/退出 AOD、连续重建安装和安装失败后的旧表盘可用性。
- 每次真机测试前清理旧 Electron 与 `pulse-core` 进程，并能说明运行的是哪次构建。

自动化、模拟器和真机结果分别报告，任何一层不能替代另一层。

## 12. 明确延后

以下内容不是 V1 遗漏，而是已决定延后：

- 其他小米手环或手表型号。
- 将任意 `.bin` 完整还原为可编辑工程。
- 从电脑实时读取手环的步数、心率、天气等数据。
- 视频表盘、模拟指针、点击跳转、JS/Lua、固件可编辑组件。
- GMF 稳定导入。
- 在线模板市场、云同步和表盘商店发布。
- Pulse 内置通用图片编辑器。

新增设备或实验组件时应扩展独立 `deviceProfile` 与能力矩阵，不能稀释 Band 10 已验证规则。
