# Pulse PC v1.1.0 设计决策记录

日期：2026-09-07  
状态：用户逐项审核通过，可以实施

## 目标

把 Pulse PC 端从混合了日常使用、首次配对和开发调试的控制台，整理成面向日常使用的三页工具；同时修复自动抢占蓝牙、无法复制错误、退出后 OronBox 仍运行，以及悬浮窗四角出现矩形灰底等问题。

本次桌面端版本发布为 `v1.1.0`。手环端应用没有功能改动时，不因桌面端版本变化而虚增自身版本号。

## 已确认的问题

1. `src/main/index.ts` 在 Pulse 启动时强制把 OronBox 的 `auto_reconnect` 设为 `true`，并主动调用 `device.connect`。
2. `OronBoxBridge` 每 30 秒执行一次断线重试，而且没有读取界面的自动重连设置。
3. 因此只打开 Pulse 就可能抢占手环蓝牙，即使用户不想连接。
4. OronBox daemon 自己保存的 `auto_reconnect=true` 也可能在启动 daemon 时连接手环；只删除 Pulse 的 `device.connect` 不足以保证纯手动连接。
5. 周围设备扫描在直接调用 OronBox `device.scan` 时能够返回设备，但 Pulse 调用可能超时；成功返回零台时，界面还会隐藏整个结果区域。用户决定不再保留这项功能。
6. `index.html` 和全局 CSS 都设置了 `user-select: none`，导致整个 PC 主窗口无法选择、复制文字；Electron 也没有提供右键复制菜单。
7. 顶栏硬编码显示 `2.0`，与真实安装包版本 `1.0.1` 不一致。
8. 当前设备管理首页同时放置连接、扫描、自动重连、设备导入、桥接模式、密钥提取和 RPK 安装，日常操作与高级操作混杂。
9. 托盘的“退出 Pulse”只退出 Pulse，OronBox daemon 仍可能占用手环蓝牙；另一个“彻底退出”选项容易混淆。
10. 悬浮窗同时启用透明窗口、Windows Acrylic/vibrancy 和原生阴影，矩形原生材质或阴影可能透出到 CSS 圆角之外。
11. 源码已经有一键诊断，但本机安装仍是 `v1.0.1`，所以安装版中看不到该功能。
12. 悬浮窗和诊断界面已经面向 Claude Code、Codex、Antigravity 三个 Agent，但额度采集内部还留有 Z Code 分支，支持范围不一致。

## 产品定位和导航

PC 端定位为日常使用工具，不把开发实现细节堆在首页。左侧导航改为三页：

1. **设备管理**：日常查看状态并手动连接或断开。
2. **运行诊断**：一键诊断、额度数据源、链路状态和可复制错误。
3. **设置与维护**：首次配对辅助、Hook、更新、兼容模式、校时和 RPK 工具。

左侧保留桌面悬浮窗开关；删除顶栏重复的悬浮窗开关。左侧 OronBox 区域只显示“后台服务正常/未连接”，点击异常状态可进入诊断页。PID、端口、协议版本和运行时长只在诊断页显示。

## 设备管理页

设备管理页只保留：

- 已配对手环的名称、型号代号、打码 MAC、连接类型和连接状态。
- 常驻的橙色蓝牙风险提示。
- “连接手环（将断开手机）”和“断开”两个明确的手动操作。
- 简化的“手环联网正常/异常”状态；不展示插件版本、请求次数和延迟等开发信息。
- 没有已配对设备时，显示“前往设置与维护完成首次配对”，不再提供 Pulse 扫描入口。

常驻风险提示必须明确说明：

- 连接 Pulse 或 OronBox 会断开手环与小米运动健康的蓝牙连接，因为手环同一时间只能连接一个蓝牙设备。
- Pulse 断开或退出后，需要在手环选择“连接新手机”，再重新连接小米运动健康，目前没有更便捷的方法。
- 连接 OronBox 后手环时间可能异常；Pulse 会尝试校时，但不宣称已经彻底解决 OronBox 问题。

不增加二次确认弹窗，以常驻警告和明确按钮文案承担告知责任。

## 纯手动连接与 OronBox 生命周期

- 删除自动重连开关及其 UI、IPC 和后台 30 秒重试逻辑。
- Pulse 启动时不自动启动 OronBox daemon，也不调用 `device.connect`。
- 用户点击“连接手环”时，Pulse 才按需启动或接入 OronBox，关闭 OronBox 的 `auto_reconnect`，再执行这一次手动连接。
- 首次设置、安装手环端和需要 OronBox 的诊断可以按需启动 OronBox，但不能顺带连接手环。
- 点击“断开”后持续保持断开，直到用户再次点击连接。
- Pulse 与已经启动的 daemon 之间可以恢复内部 RPC；RPC 恢复不等于连接手环。
- 每次手动连接成功后，Pulse 尽力调用 `device.sync.time`。成功时保持安静；失败时在界面和诊断报告中给出可复制警告。
- 设置与维护页提供“重新同步手环时间”按钮，仅在手环已连接时可用。

## 退出行为

- 窗口右上角关闭按钮只隐藏到托盘，并在提示文字中说明。
- 托盘只保留一个“退出 Pulse”。
- 托盘退出必须依次尝试断开手环、停止 OronBox daemon，然后退出 Pulse。
- 删除“普通退出”和“彻底退出”两个相近选项；退出后 OronBox 不得继续占用蓝牙。

## 删除的设备功能

完整删除下列 Pulse 功能及其孤立代码：

- 周围设备扫描卡片。
- 无设备时的扫描入口。
- 扫描结果区域。
- `device.scan` IPC 和 preload 暴露。
- Pulse 手动添加设备表单。
- `device.import` IPC 和 preload 暴露。
- 自动重连设置和重试逻辑。

首次配对明确交给 OronBox。Pulse 不再维护第二套配对入口。

## 设置与维护页

按日常用户能理解的顺序组织：

1. 显示桌面端真实版本，并提供“检查更新”。发现新版时打开对应 GitHub Release 页面，不做静默自动更新。
2. 首次设置说明与 OronBox 安装状态检查。
3. 从小米运动健康/小米健康研究日志中提取 authkey；解析只在本机完成。
4. 引导用户让手环进入“连接新手机”，在 OronBox 内扫描、填写 authkey 并完成首次配对。
5. 安装或重新安装 Pulse 内置手环应用。
6. Claude Code Hook 的安装、重新安装和卸载。
7. 手环校时按钮。
8. 高级兼容模式：默认固定使用 Pulse 直连；FetchBridge 插件模式改名为“兼容模式”，只在直连异常时由诊断建议使用。
9. 开发者工具：保留任意 `.rpk` 的选择、拖入和手动推送，方便安装用户以后开发的其他手环应用。非内置 RPK 的兼容性不由 Pulse 保证。

任何 RPK 都必须由用户点击确认后才传输，不允许拖入即自动安装。

## 运行诊断页

页面顺序固定为：

1. 一键完整诊断，以及“复制诊断报告”。
2. Claude Code、Codex、Antigravity 三个数据源的额度和有效性。
3. 手环、OronBox daemon、协议版本和联网桥接状态。
4. 最近异常日志，以及“复制全部日志”和“清空日志”。

Claude Code Hook 管理移到设置与维护页。诊断报告和日志复制内容必须自动脱敏：不包含 authkey、token、完整 MAC 或用户目录中的敏感绝对路径。

## 文字选择和复制

- PC 主窗口的普通文本允许鼠标选择并支持 `Ctrl+C`。
- 标题栏、按钮、开关、拖放区域和悬浮窗继续禁止误选文字。
- 异常日志支持一键复制全部日志，包含时间、来源和消息。
- 一键诊断支持一键复制脱敏后的诊断报告，方便粘贴到 GitHub Issue。

## 真实版本和更新

- 顶栏不再硬编码 `2.0`，读取 Electron `app.getVersion()`，与 `package.json` 和安装包一致。
- 设置与维护页显示同一真实版本。
- “检查更新”查询公开 GitHub 仓库的最新 Release；仅提示并打开 Release 页面，不后台下载、不静默安装。
- 本次桌面版统一更新为 `1.1.0`，同步 `package.json` 和 `package-lock.json`。

以后由 Codex 执行版本发布时，固定完成以下双端验收：

1. 更新源码版本、文档和测试。
2. 推送 GitHub `main` 并等待 CI 通过。
3. 推送版本 Tag，触发 GitHub Actions 构建 Release。
4. 核对 Release 安装包与 SHA-256。
5. 在作者电脑安装同一 Release。
6. 核对 GitHub Release、本机安装版和源码版本三者一致。

## 支持的 Agent

公开支持范围统一为：

- Claude Code
- Codex
- Antigravity

删除 Z Code 的内部采集、类型、诊断和文案残留。README 说明三者的数据来源；Claude Code 实时会话通过 Hook 接入，其他 Agent 沿用各自已有采集方式。

## 悬浮窗

- 保留折叠胶囊和展开卡片两种状态。
- 保留左侧栏和托盘的显示/隐藏入口。
- 记住用户上一次选择的显示或隐藏状态；首次安装默认显示。
- 去掉原生 Acrylic、vibrancy 和矩形窗口阴影，保留透明 BrowserWindow。
- 视觉由 CSS 半透明背景、圆角、边框和内部高光完成；优先保证折叠与展开时四角完全透明，即使桌面背景模糊感略有降低。

## 验收标准

- 仅启动 Pulse，OronBox 未被自动拉起，手环和手机蓝牙连接不受影响。
- 未点击连接时，60 秒内不存在任何 `device.connect` 请求。
- 点击连接只触发一次手动连接；断开后不自动重连。
- 托盘退出后 Pulse 与 OronBox 进程都结束，手环连接已断开。
- PC 普通文字可选择并 `Ctrl+C`；日志和诊断报告可一键复制且通过脱敏测试。
- 主界面不再出现扫描、扫描结果、设备导入和自动重连。
- 顶栏、设置页、源码、安装包和 GitHub Release 均显示 `1.1.0`。
- 悬浮窗四个角在浅色和深色桌面背景下均为透明。
- `npm test`、`npm run build`、安装包构建和 GitHub CI 全部通过。
- GitHub Release 与作者电脑安装版均更新到 `v1.1.0`。
