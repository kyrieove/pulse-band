# 故障排查

这一页记的是几个小时试错换来的结论。**卡住了先看这里，别自己重新摸索。**

---

## 一、先分清「断开连接」和「解绑」

这两个词长得像，成本差一个数量级。搞混会白白多跑一遍取密钥流程。

| 动作 | 怎么做 | authkey 换不换 | 成本 |
|---|---|---|---|
| **A. 进「连接新手机」模式** | 手环上：设置 → 系统操作 → 连接新手机 | ❌ **不换** | 手环上点一下。退出后手机自己重连回来 |
| **B. 真·解绑重绑** | 小米运动健康里删除设备 → 重新扫码绑定 | ✅ **每次都换** | 要重新走一遍取密钥 |

[配对指南](手环配对指南.md)第 4 步说的是 **A**，不是 B。

手环在「手机」和「电脑」之间来回切换，成本就是在手环上点一下，**不需要重新绑定，也不需要换密钥**。

---

## 二、连接失败：先看是通道问题还是密钥问题

OronBox 的两条报错含义完全不同，对应两种完全不同的修法。**日志在 `%APPDATA%\OrPudding\OronBox\logs\`**（注意是 `Roaming`，不是 `LocalAppData`），看文件头写着 `role=backend` 的那个。

### `CONNECT_FAILED: No RFCOMM channel available`

**通道开不了。** 蓝牙层就没连上，后面的认证一步都没走到。

依次检查：

1. 手环有没有进「连接新手机」模式？手环上：**设置 → 系统操作 → 连接新手机**（[指南第 4 步](手环配对指南.md)）。**这是最常见的原因**——手环被手机连着时不接受新连接。
2. 手环在不在电脑蓝牙范围内？
3. 手机上的小米运动健康是不是又把手环抢回去了？把手机蓝牙关掉再试一次。

### `Auth HMAC mismatch. Check that the auth key is correct.`

**看到这条要高兴。** 它意味着蓝牙、通道、协议全对，问题收敛到一个字符串——密钥错了。

1. 你是不是把 `deviceKey` 整串（约 42 位）都填进去了？**开头那段设备 ID 要去掉，只要末尾 32 位。**
   用 Pulse 的「从手机日志里取 authkey」功能可以自动处理这一步。
2. 你的日志是不是重新绑定之前导出的？重新绑定后密钥会换，要重新导一次日志。
3. 日志里有多处密钥？**取最后一次出现的那个。**

### 握手成功长这样

```
RfcommDriver – SPP connected channel=5 … connectMs=2469
DeviceManager – starting authentication
XiaomiAuthSystem – starting auth
XiaomiAuthSystem – received device verify, building confirm
DeviceManager – event: authenticated
```

## 三、走不通的路，别再试

这几条都实测过，全是死路：

| 想法 | 为什么不行 |
|---|---|
| **用小米账号同步 authkey** | PC 和手机版**都是坏的**。OronBox 的登录流程需要完成 2FA 后的浏览器会话 cookie，Windows 桌面版没有内嵌 WebView 去捕获它，会报 `Verified Xiaomi 2FA session still requires account credentials after retry`。手机版是同源代码，报同样的错 |
| **在 Windows 蓝牙设置里手工配对手环** | 没用。OronBox 走自己的 SPP 通道，不需要系统层面的配对 |
| **`device.connect` 反复重试** | 只能解决通道问题，对密钥错误无效。看到 `Auth HMAC mismatch` 再怎么重试都一样 |
| **用「取消连接」中断操作** | **别用。** 它内部会调用断开设备，"取消"的副作用是把手环断掉 |
| **拿表盘自定义工具里显示的密钥** | 那是缓存。重新绑定后它显示"没变"，那正是它错了的证据 |

## 四、密钥找不到 / 找错字段

日志里有好几个长得像密钥的字段，只有一个是对的：

| 字段 | 是不是要的 |
|---|---|
| `deviceKey` | ✅ 是，但**要去掉开头的设备 ID**，只取末尾 32 位 |
| `encryptKey` | ✅ 是，本来就是 32 位，直接用。**OronBox 实际使用的就是这个字段** |
| `authKey` | ❌ 本地日志里恒为空 |
| `beaconKey` | ❌ 蓝牙广播用的，和认证无关 |
| `irqKey` | ❌ 无关 |

如果 Pulse 同时解析出 `deviceKey` 和 `encryptKey` 且两者不一致，**先试 `encryptKey`**。

## 五、Pulse 侧的问题

### 手环上的应用打开了，但数据不动

**先确认桥接模式**：Pulse → 设备管理 → **米环互联 FetchBridge** 卡片。默认是**直连模式**。

### 直连模式下

看卡片上的 **累计代理请求** 计数：

| 你看到的 | 说明 | 怎么修 |
|---|---|---|
| 显示「已停止代理」 | 响应器没起来 | 点「启动代理」；仍不行说明 FetchBridge 插件被 OronBox 界面占着，关掉 OronBox 窗口再试 |
| 请求数一直是 0 | 手环没在发请求 | 手环上把 Pulse 应用打开并保持亮屏；确认设备管理页顶部是**已连接** |
| 请求数在涨、有时延数字 | 链路正常，是**数据源**没数据 | 往下看 |

> 直连模式和插件模式**互斥**。如果你在 OronBox 里也开着 FetchBridge 插件监听同一个包名，同一个请求会被应答两次，症状是手环上数据偶发闪烁或回退到旧值。Pulse 切模式时会自动关掉另一边，但如果插件被 OronBox 界面持有就关不掉——**把 OronBox 窗口关掉**即可。

### 插件模式下

OronBox → 插件 → 已安装 → 米环互联 FetchBridge → 「监听与统计」：

| 你看到的 | 说明 | 怎么修 |
|---|---|---|
| 没有 `com.codeisland.band` 这一条 | 插件没在监听 | 见[配对指南附录](手环配对指南.md)，手动添加包名并点「开始监听」 |
| 有这一条但开关是关的 | 监听被关掉了 | 把开关打开 |
| 请求数一直不涨 | 手环没在发请求 | 手环上把 Pulse 应用打开并保持亮屏 |
| 请求在涨但**失败**也在涨 | 请求发出去了，Pulse 没应答 | 确认 Pulse 正在运行。「最近地址」应该是 `http://127.0.0.1:8765/...` |
| 请求成功、`HTTP 200`，但手环上还是空的 | 链路正常，是**数据源**没数据 | 往下看 |

链路正常但没数据，检查这三条：

1. Pulse 里「设备管理」页顶部是不是显示**已连接**？
2. Claude Code 的 hook 装了吗？Pulse →「运行诊断」→ 看「Claude Code 接入」卡片是不是「已安装」。
3. 装了 hook 之后**重开过 Claude Code 会话**吗？hook 只在新会话生效。

### 点了「安装 Hook」但悬浮岛还是没反应

- 装完必须**重开一个 Claude Code 会话**。
- 检查 `~/.claude/settings.json` 里有没有含 `pulse-hook.cmd` 的条目。
- 如果你的 `settings.json` 被改坏了，安装前的备份在同目录的 `settings.json.pulse-backup`。

### 推送 `.rpk` 失败

手环必须**先连上**才能装包。确认「设备管理」页显示已连接后再点推送。

> ⚠️ 这个 `.rpk` 只在作者本人的小米手环 10 上验证过。如果连上了但推送仍然失败，请提交 issue 并附上 OronBox 的日志（记得**先把日志里的密钥打码**）。

## 六、提 issue 之前

请附上：

- Windows 版本、手环型号、OronBox 版本
- `%APPDATA%\OrPudding\OronBox\logs\` 里 `role=backend` 那个文件的相关片段
- Pulse →「运行诊断」页的截图

**⚠️ 贴日志前先把 authkey 打码**（保留前 4 位后 4 位就够定位了）。那串东西等于你手环的钥匙。
