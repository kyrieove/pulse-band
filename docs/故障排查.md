# 故障排查

排查问题时，先在 Pulse 中进入「运行诊断」，点击「一键完整诊断」。诊断只读取当前状态，不会修改蓝牙、设备或其他配置。

---

## 一、「连接新手机」与重新绑定的区别

| 操作 | 方法 | 是否更换密钥 | 后续操作 |
|---|---|---|---|
| 进入「连接新手机」模式 | 手环上：设置 → 系统操作 → 连接新手机 | 否 | 切回手机时在小米运动健康中重新连接 |
| 重新绑定 | 在小米运动健康中删除设备，再扫码绑定 | 是 | 重新导出日志，在配置向导中重新导入 |

[配对指南](手环配对指南.md)第 3 步使用的是「连接新手机」。手环在手机和电脑之间切换时，不需要重新绑定。

---

## 二、连接失败

连接失败时，「手环」页会显示失败所在的步骤（启动服务 / 查找手环 / 建立连接 / 验证身份）和提示信息。

| 提示信息 | 含义 | 处理方法 |
|---|---|---|
| 手环蓝牙通道已被占用，请在手环上选择「连接新手机」进入可连接模式 | 蓝牙连接未建立，通常是手环仍与手机保持连接 | 在手环上选择「连接新手机」；如仍失败，关闭手机蓝牙后重试 |
| 连接超时，请确认手环位于电脑蓝牙通信范围内并保持亮屏 | 手环未响应 | 将手环靠近电脑并点亮屏幕后重试。连接过程中需要在手环上接受配对请求；第一次连接时还需要在电脑弹出的 Windows 蓝牙配对窗口中点击允许 |
| 未找到目标手环，请确保手环蓝牙已开启 | 电脑未找到配置中的手环 | 确认电脑蓝牙已开启；更换过手环时需要重新运行配置向导 |
| 设备认证信息失效或不匹配 | 蓝牙连接已建立，密钥验证未通过 | 见下方「密钥验证失败」 |

### 密钥验证失败

按以下顺序检查：

1. 导出日志之后是否重新绑定过手环。重新绑定会更换密钥，需要重新导出日志，然后在「手环」页 →「配置手环」中选择「重新导入新日志覆盖」。
2. 使用的日志是否为最新。`ResearchLog` 下有多个 `research-<数字>` 文件夹时，应选择修改时间最新的一个。
3. 更换日志来源后重试：小米健康研究导出的 `XiaomiFit.main.log`，或小米运动健康「上传日志」生成的 zip 文件。

> 在手环上重新选择「连接新手机」，或在 Windows 蓝牙设置中删除手环后重新配对，都不能解决密钥验证失败。

## 三、运行诊断检查项

「一键完整诊断」对每一项给出「通过」「警告」或「失败」。

| 检查项 | 警告或失败的含义 | 处理方法 |
|---|---|---|
| Pulse 状态服务 / Hook 接收服务 | 本机服务未启动或无响应，可能是端口 `8765`（状态服务）或 `41789`（Hook 服务）被占用 | 从托盘退出 Pulse 后重新打开；仍失败时检查端口占用 |
| Claude Code Hook | Hook 未安装或转发脚本缺失 | 「设置」→「检测 Agent 接入」→ Claude Code 一行点击「修复」 |
| 设备守护进程 | `pulse-core` 未启动 | 未连接手环时出现此警告属于正常情况，`pulse-core` 在连接手环时启动。连接后仍有警告时，退出并重新打开 Pulse |
| 手环连接 / 手环联网桥接 | 手环未连接 | 在「手环」页连接手环 |
| 内置手环应用 | 安装目录中缺少 `band-app.rpk` | 重新安装 Pulse |
| AI 额度数据 | 暂无额度数据 | 确认对应 Agent 已登录并使用过；Pulse 刚启动时需要等待数据刷新 |

---

## 四、手环上的 Pulse 应用没有数据更新

按以下顺序检查：

1. 「手环」页是否显示已连接。
2. 手环上的 Pulse 应用是否在前台，屏幕是否亮起。
3. Claude Code hook 是否已安装：「设置」→「检测 Agent 接入」中查看 Claude Code 一行。
4. 安装 hook 后是否重新打开了 Claude Code 会话。hook 只对新会话生效。

## 五、Agent 状态

### Hook 已安装，但状态不更新或显示未安装

- 安装 hook 后需要重新打开 Claude Code 会话。
- 旧版本安装的 hook 缺少 `UserPromptSubmit` 事件，检测结果会显示「未安装」。点击「修复」重新安装即可，安装时会先移除旧条目，不会产生重复项。
- 检查 `~/.claude/settings.json` 中是否有包含 `pulse-hook.cmd` 的条目。
- 需要恢复 `settings.json` 时，安装前的备份位于同目录的 `settings.json.pulse-backup`。

### 会话状态的更新延迟

三个 Agent 的状态来源不同，更新延迟如下：

| Agent | 识别方式 | 开始延迟 | 说明 |
|---|---|---|---|
| Claude Code | hook 事件（`SessionStart` / `UserPromptSubmit` / `PreToolUse` / `PostToolUse` / `Stop`） | 即时 | 需要安装 hook。未安装时改为读取会话记录文件，思考过程中该文件不更新，无法识别「思考中」状态 |
| Codex | 监听 `~/.codex/sessions` 下的会话文件 | 取决于 Codex 写入文件的时机 | Codex 不提供 hook |
| Antigravity | 轮询本地 language_server | 约 5 秒 | 轮询间隔为固定值 |

Antigravity 的结束判定有 4–40 秒的自适应等待时间，用于避免把任务中途的停顿判定为已完成。等待历史较长的会话，结束后需要更长时间才会显示「已完成」。

## 六、快应用或表盘安装失败

- 安装前需要先连接手环，确认「手环」页显示已连接。
- 快应用只支持 `.rpk` 文件，表盘只支持 `.bin` 文件。
- 提示「已存在于手环，无需重复安装」表示该表盘已在手环上，不是错误。
- 内置表盘由设备自带，不能删除。

> 快应用和表盘功能仅在作者的小米手环 10 上验证过。已连接但安装仍失败时，请在 issue 中附上诊断报告。

---

## 七、提交 issue

请提供以下信息：

- Windows 版本、Pulse 版本（「设置」→「版本与环境」）、手环型号
- 「运行诊断」→「一键完整诊断」→「复制报告」得到的文本

诊断报告已自动脱敏，不包含密钥和完整蓝牙地址。附加其他日志或截图时，请先确认其中不包含密钥。
