# Pulse 2.0 页面布局规范 (Screen & Layout Specifications)

本文档定义 Pulse 2.0 三大核心主屏（概览、手环、设置）以及桌面悬浮小岛 (MiniBar) 的完整页面级布局、栅格结构、信息层级、状态流转与实现数据边界。

---

## 1. 全局窗体与布局栅格 (Window & Layout Grid)

### 1.1 窗口与工作区参数
- **窗口物理尺寸**：设计基准尺寸为 `920px × 640px`（支持系统响应伸缩，最小允许尺寸 `840px × 580px`）。
- **水平分割**：
  - 左侧边栏 (Sidebar)：固定 `200px` 宽，不可折叠。
  - 右侧主工作区：`flex-1`，自适应拉伸。
- **垂直分割**：
  - 顶部自绘标题栏 (TopBar)：固定 `40px` 高，主标题固定显示 **Pulse 2.0**。
  - 内容可视区域：`600px` 高，超出自动产生平滑自适应细滚动条。
- **间距节奏**：
  - 工作区内边距：`p-6 (24px)`。
  - 主块垂直间距：`space-y-5 (20px)`。

## 2. 概览页规范 (Screen 1: Overview)

### 2.1 核心信息流与视觉层级（硬性先后顺序）
概览页是用户日常核心看板，**信息流必须严格遵守以下自上而下的物理顺序**：

```text
┌──────────────────────────────────────────────────────────┐
│ 1. 手环连接状态卡片 (BandConnectionCard)                  │
│    - 设备名称: Xiaomi Smart Band 10                      │
│    - 状态标识: 已配置手环 · 当前连接状态                   │
│    - 最后同步状态: (如“最后同步：刚刚”或“尚未同步到手环”)   │
├──────────────────────────────────────────────────────────┤
│ 2. 连接 / 断开主操作 (PrimaryButton / SecondaryButton)   │
├──────────────────────────────────────────────────────────┤
│ 3. 连接阶段反馈 (ConnectionProgress: 四阶段状态流转)      │
│    - 启动设备服务 ➔ 查找手环 ➔ 建立连接 ➔ 验证凭据        │
├──────────────────────────────────────────────────────────┤
│ 4. Agent 状态与额度区 (Agent Quota Section)              │
│    - 仅展示已检测或启用的 Agent                          │
│    - 默认态：名称、主要额度、重置时间、当前状态、运行计时 │
│    - 展开态：该 Agent 实际提供的其他额度、更新时间、详细状态 │
└──────────────────────────────────────────────────────────┘
```

### 2.2 详细设计与脱敏要求
1. **设备信息防泄露设计**：
   - 严禁展示完整 MAC 地址，严禁提供“点击查看完整地址”开关；
   - 界面上仅标识设备型号（`Xiaomi Smart Band 10`）与通用描述“`已配置手环`”；
   - 错误提示或认证说明文案一律使用“**设备凭据**”或“**认证信息**”，严禁在 UI 打印凭据原文。
2. **连接生命周期反馈**：
   - 未连接 (`idle`) 态：明确说明“手环未连接”，电脑端 Agent 额度正常查看；
   - 连接中态：在按钮原位显示阶段文案，并展开 `ConnectionProgress`；
   - 已连接 (`connected`) 态：显示“已连接”，并展示“最后同步：刚刚”。
3. **数据驱动的 Agent 列表**：
   - 杜绝全局“自动刷新 · 5 小时窗口”死板标牌；
   - 各卡片仅消费本 Agent 真实具备的数据字段。

## 3. 手环管理页规范 (Screen 2: Band Management)

### 3.1 页面布局与信息架构 (自上而下)

1. **设备状态主卡片 (Device Card)**：
   - 设备型号名：Xiaomi Smart Band 10；
   - 连接状态徽章（如“已连接”或“未连接”）；
   - 主操作按钮：“连接手环” / “断开连接”；
   - 右上角次要操作：“更换手环”（点击进入更换流程，覆盖前明确说明影响）。
2. **Pulse 快应用版本卡片 (Band Quick App Card)**：
   - 展示手环端配套快应用当前版本；
   - 若检测到内置新版本，显示“有可用更新”并提供“推送更新至手环”按钮。
3. **高级工具区域 (CollapsibleAdvancedSection)**：
   - **首版仅包含唯一已确认能力：“推送其他快应用”**；
   - **默认必须强制折叠**；
   - 展开后提供拖入或选择单个 `.rpk` 文件的安装入口，展示文件名与大小，用户确认后推送；
   - 严禁在页面出现信道质量、固件版本、蓝牙底层包日志、协议重置等未确认功能，严禁出现不可用的表盘市场按钮。

## 4. 设置页规范 (Screen 3: Settings)

### 4.1 四组设置项架构
设置页严格分为四个 `SettingsGroup` 卡片，不增加第二套导航，**高级维护的视觉权重必须降到最低**：

```text
┌──────────────────────────────────────────────────────────┐
│ 1. 外观设置 (Appearance)                                  │
│    - 主题模式：亮色 (Light - 默认) / 深色 (Dark)           │
│    - 桌面悬浮窗 (MiniBar)：显式开启 / 关闭 Toggle 开关      │
├──────────────────────────────────────────────────────────┤
│ 2. Agent 监控设置 (Agent Integration)                    │
│    - 各已检测 Agent 的显示控制开关 (Claude / Codex / etc.) │
├──────────────────────────────────────────────────────────┤
│ 3. 手环同步设置 (Band Synchronization)                   │
│    - 设备重新配置引导入口                                │
├──────────────────────────────────────────────────────────┤
│ 4. 高级维护 (Maintenance & Diagnostics)                  │
│    [视觉权重最低：弱边框、小字号 text-xs、置于页面最下方]    │
│    - 运行诊断中心入口 (打开二级诊断面板)                 │
│    - 脱敏运行日志查看与一键复制                          │
│    - 诊断报告导出                                        │
│    - 检查应用版本与更新                                  │
└──────────────────────────────────────────────────────────┘
```

## 5. 桌面悬浮小岛规范 (MiniBar Specification)

- **尺寸**：`320px × 36px`，药丸胶囊形态。
- **展示原则**：
  - 仅展示已启用的 Agent；
  - 仅展示精简额度数值、当前运行状态与运行计时；
  - 绝不做成微缩版复杂 Dashboard。
- **点击交互**：点击立即呼出主视窗并激活“概览”页。
- **主题联动**：跟随系统或主应用在 Light（浅白磨砂玻璃）与 Dark（暗夜磨砂玻璃）间自适应切换。

## 6. Implementation Data Boundary（实施数据来源边界）

为确保 Pulse 2.0 在工程推进过程中不发生数据造假、不产生假成功入口，本设计规范对所有界面元素设立严格的**数据来源边界**：

| 分类标识 | 含义与工程准则 |
|---|---|
| **Existing** | **当前真实后端已能提供**：当前 IPC / 后台服务中已有真实数据源（如现有连接状态、既有 Agent 会话状态与额度、已有的诊断日志）。在当前子项目 1 实现时，作为真实功能正常渲染。 |
| **Future - Subproject 2** | **由子项目 2 交付**：无外部工具依赖的完整首次设置向导、手机日志本地内存解析、Windows DPAPI 凭据安全持久化、Windows 原生系统蓝牙配对。本阶段保留在设计规范中，但在子项目 1 代码中**绝不制作可点击的假成功入口**。 |
| **Future - Subproject 3** | **由子项目 3 交付**：内置与第三方 RPK 传输校验安装闭环、历史内部命名彻底清理。本阶段在 UI 上仅作结构预留与高级折叠规范，绝不伪造安装成功事件。 |

### 6.1 各页面元素的数据边界审计对照

| 页面 | 界面元素 | 数据边界归属 | 子项目 1 (当前) 渲染准则 |
|---|---|---|---|
| **概览** | 手环连接状态 (已连接/未连接) | **Existing** | 消费真实底层状态映射，无假成功 |
| **概览** | 连接/断开操作 | **Existing** | 调用现有连接/断开动作 |
| **概览** | 连接四阶段指示 (启动/查找/连接/认证) | **Existing (已部分具备)** / **Future - Subproject 2 (完整细粒度)** | 映射真实中间态，不可伪造阶段全部完成 |
| **概览** | Agent 额度与状态卡片 | **Existing** | 真实数据驱动渲染，无数据不伪造 |
| **手环** | 设备型号与已配置标识 | **Existing** | 显示真实配置的手环，隐去敏感明文 |
| **手环** | “更换手环”流程入口 | **Future - Subproject 2** | 仅作规范与设计布局，不可制作可完成伪向导 |
| **手环** | Pulse 快应用版本与更新提示 | **Existing (基础版本查询)** / **Future - Subproject 3 (自动化更新)** | 依据本地真实快应用元数据呈现 |
| **手环** | 高级区域：推送其他快应用 | **Future - Subproject 3** | 默认强制折叠，未实现时保持安全待命 |
| **设置** | 外观主题切换 (Light/Dark) | **Existing (子项目 1 核心交付)** | 实时生效并持久化 |
| **设置** | 悬浮窗 (MiniBar) 开关 | **Existing** | 调用现有 MiniBar IPC 显示控制 |
| **设置** | 高级维护：诊断与脱敏日志 | **Existing** | 保留现有完整诊断能力与脱敏日志导出 |
