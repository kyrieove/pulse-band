## 阶段 1：手环剩余口径（验证 commit `da8cca7`）

这是 ui-fix-1 的改动，**从来没在真机上看过**。风险点是标题变长后被小屏裁掉。

要主线看手环屏幕并回答：

1. 卡片标题是不是「**5h 剩余**」「**7d 剩余**」？有没有被裁成「5h 剩」之类？
2. 百分比是**剩余**方向吗？拿客户端概览页同一个 Agent 的数字对照——客户端显示「剩余 80%」时手环也该是 80%，不是 20%。
3. 进度条填充方向和数字一致吗（数字越小、填充越短）？
4. 额度未知时显示的是 `--` 还是 `0%`？两者必须能区分。

## 阶段 2：手环连接中断提示（验证 commit `b856f06`）

ui-fix-2 新增了 `handleDisconnect()`，同样没真机验证过。

让主线**主动断开**（关蓝牙或走远），然后看手环：

1. 是否出现持续可见的「连接中断」提示？
2. 原来的 `Running` 动词有没有被覆盖掉？**残留 Running 是这次要抓的主要缺陷**——它会让人以为任务还在跑。
3. 指示灯是否变红？
4. 恢复连接后能否自动回到正常显示？

## 阶段 3：表盘三个 RPC（最高风险）

**风险来源**：`WatchFacePage.tsx` 和 `watchface-service.ts` 里的字段形状是照 `core/src/rpc.rs` 的 **Fake 分支**写的，真机返回的字段名、类型、数量都可能不一样。这是整个表盘功能最可能出问题的地方。

现成脚本，按顺序跑：

```bash
node scripts/verify-watchface-list.mjs
node scripts/verify-watchface-set.mjs
node scripts/verify-watchface-install.mjs watch-face
```

要核对的：

1. **list**：真机返回的每个 item，字段名和 `id / name / is_current / can_remove / version_code / can_edit / background_color / background_image / style` 是否逐一对得上？少了哪个、多了哪个、类型不符的，全列出来。
2. **set**：切换是否真的生效（手环表盘变了）？往返耗时多少秒？**如果接近或超过 60 秒，说明 `watchface-service.ts` 的 set 超时设小了**，报告里写明实测耗时。
3. **install**：`result_code` 是多少？`2` = 新装成功，其他 = 设备上已存在。实测耗时多少？300 秒超时够不够？

## 阶段 4：表盘页 UI（已连接态）

前面三个阶段都过了再做这个。启动应用，进「表盘」页：

1. 列表能渲染出来吗？当前表盘有没有明确标记？
2. 点一个非当前表盘 → 「设为当前表盘」，手环上是否真的换了？切换期间其他项是否正确禁用？
3. 拖入 `watch-face/BetaUI-黑塔.bin` 安装，观察长时 busy 态的文案是否合理（**不该有假进度条**）。
4. 装一个设备上已有的表盘，看是否显示「已存在于手环，无需重复安装」且用**成功色**，不是错误色。

## 阶段 5：手环管理页（验证 commit `8b3845a`）

ui-fix-5 重写了这一页的主操作，真机路径没验证过：

1. 未连接 → 主操作是不是「连接手环」？连接失败 → 是不是「重试连接」且能指出失败在哪一步？
2. 已连接 → 主操作是不是「安装 / 重装 Pulse 手环端」？
