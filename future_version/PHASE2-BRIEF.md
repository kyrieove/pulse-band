## 第 −1 条 · 证据规则（优先于本文件其余一切内容）

这一阶段的产物是**证据**，不是进度。以下规则违反任意一条，本阶段判定不通过，
即使 `transport.md` 写得再完整：

1. **禁止写出你没有亲眼在命令输出里见过的字节、路径、版本号、包号、字段偏移。**
   记不清就重跑命令，不许凭印象补。
2. **每一条结论必须附「复现三件套」**：① 产生它的完整命令原文；② 该命令输出的原文摘录
   （不是你的转述）；③ 定位信息（pcapng 路径 + sha256 + 包号或字节范围）。
   三件套缺任何一件，该条只能标「仍是假设」。
3. **禁止使用「已确认 / 已验证 / 验证通过 / 正常 / 符合预期」这类词，除非紧跟同一段落里
   就有对应的命令与输出原文。** 空口的「已确认」按虚报处理。
4. **禁止用你自己的实现去验证你自己的理解。** round-trip 测试、自己写的编码器、
   「没报错」「没回 NAK」都不是协议事实的证据。证据只能来自 pcapng 里的原始字节。
5. **禁止删除、覆盖、重新生成 pcapng 来「重来一次」。** 每次抓包用新文件名，全部保留。
   我要能拿着你留下的 pcapng 重新推出你的每一条结论。
6. **报告失败优于编造成功。** 任何一步没做成、被 UAC 拦住、抓包内容不可分析 ——
   直接写「没做成 + 原因 + 原始输出」。这不算你的失败，是本阶段的正常结果之一。
   反过来，一份看起来漂亮但推不回去的报告，是本阶段唯一不可接受的结果。
7. **每一步做完，先在终端打印该步的验证输出，再进下一步。** 不许攒到最后一次性总结。

## 第 4 步 · 写 `docs/protocol/transport.md`

每一条要么带完整的「复现三件套」并标 `来源：自己抓包 · 2026-09-08`，
要么标 `仍是假设`。**不允许第三种状态，不允许填猜测值。**
文件开头记 pcapng 的路径与 sha256。

至少覆盖：

- magic 是否 `A5 A5`
- type / seq / len 的位置与字节序
- 校验机制是什么；**若是 CRC，必须分别给出覆盖范围（第几字节到第几字节）、
  输入输出是否反射、最终异或值** —— 这三项缺任何一项，整条校验结论标「仍是假设」
- 各 type 的载荷格式
- 首包方向：建链后手环先发还是主机先发

**CRC 参数的认定门槛**：拿你推定的参数，对 pcapng 里**至少 3 个长度互不相同的真实帧**
分别计算，逐帧与抓包里的校验字段比对，把 3 组（帧号 / 覆盖字节 / 算得值 / 抓到值）列成表。
只对上 1 帧不算确认。**禁止反推**：不许调参数去凑某一帧，再宣布参数已确认。

留下至少一个完整帧作阶段 3 的独立测试向量（真实字节进 `core/tests/fixtures/`，文档里只写结构）。
